1. PURPOSE

This document is the content-control map for the complete Janavani
website redesign.

It prevents repeated work and prevents the redesign from becoming a
simple replacement of the existing website.

Core rule

Merge and strengthen. Do not simply replace.

Existing useful material remains part of the new website unless it is
inaccurate, duplicated, obsolete, or strategically misplaced.

The website is a public-facing brochure/showcase and discovery layer. It
is not the Janavani application itself.

3. CONTENT STATUS LANGUAGE

Every capability must be classified as one of three states.

NOW

Verified or currently available.

Examples: - working citizen-assistance journey; - Telegram interface; -
complaint/document workflow; - office search/fallback concepts; -
document/PDF generation; - current public resources.

BUILDING

Actively being developed.

Examples: - Janavani Web App; - shared web citizen journey; - improved
civic intelligence; - stronger AI-assisted capabilities.

FUTURE

Research, roadmap or long-term direction.

Examples: - advanced governance intelligence; - tracking and
escalation; - Android/iOS; - WhatsApp/Messenger; - expanded API; -
decentralised infrastructure; - community-owned infrastructure; -
Freenet and related technologies.

Rule

Never present a future capability as if it already exists.

6. HOW IT WORKS --- THE CITIZEN JOURNEY

Primary job

Make the product understandable visually in under one minute.

This should be the most visual page.

Main flow

01 DESCRIBE
What happened?

02 UNDERSTAND
What kind of issue is this?

03 IDENTIFY
Which authority / office / pathway?

04 PREPARE
What document or action is appropriate?

05 ACT
Take the appropriate civic action.

06 FOLLOW
Keep records and continue participation where supported.

Current verified journey

The current Telegram workflow has demonstrated a basic
complaint-generation journey through issue description/classification,
document selection, district, office search/fallback, identity, preview,
format selection, document generation and PDF download.

The website should describe this accurately as a current interface
capability, without implying that every future step is already
production-complete.

Visuals

Use: - process infographic; - architecture diagram; - current-vs-future
pathway; - optional interface screenshots later.

Avoid decorative charts.

Citizen takeaway

Janavani does not decide for the citizen. It helps the citizen
understand the path and act more effectively.

11. CHART AND INFOGRAPHIC RULE

Every visual must explain something that text alone cannot explain as
efficiently.

Approved uses: - process diagrams; - architecture diagrams; - lifecycle
diagrams; - current/building/future maps; - citizen-vigilance cycles; -
conceptual comparisons.

Do not invent statistics.

Do not use fake charts.

Do not use visuals merely as decoration.

12. SEO + AI SEARCH CONTENT RULES

The redesign should support conventional search and generative/AI search
by making the site an excellent information source.

Every major page should have:

one clear H1;

logical H2/H3 hierarchy;

concise direct answers;

meaningful internal links;

unique title;

unique meta description;

canonical URL;

Open Graph metadata;

crawlable HTML;

descriptive image alt text;

useful FAQ content where appropriate;

structured data only where it accurately describes visible content.

Core entity consistency

Use consistent terminology:

Janavani
Janavani --- The Infrastructure of Citizen Voice
Janavani citizen governance platform
Janavani Web App
Janavani Telegram Bot

Do not create contradictory descriptions.

13. ACCESSIBILITY

Maintain: - semantic HTML; - keyboard accessibility; - visible focus; -
readable line length; - adequate contrast; - reduced-motion support; -
accessible controls; - mobile usability.

Do not use ARIA merely for decoration.

14. MOBILE / APP-LIKE FEEL

The website should visually feel closer to a civic product than a static
brochure while remaining a lightweight static site.

Use: - strong touch targets; - clear CTA hierarchy; - compact
navigation; - progressive disclosure; - short content blocks; - visual
process flows; - sticky/quick-access elements only where useful; -
consistent status badges.

Do not turn the brochure into the Web App.

16. FINAL CONTENT DECISIONS

KEEP

Useful existing explanations, philosophy, practical guidance, verified
capabilities, current resources.

MERGE

Overlapping old/new explanations into one stronger narrative.

REWRITE

Outdated positioning, repetitive sections, unclear future claims, weak
headings.

MOVE

Technology material → Resources.
Long-term architecture → Vision.
Participation links → Get Involved.
Workflow → How It Works.

FUTURE

Features not yet operational.

REMOVE

Duplicate claims, decorative content, unsupported statistics, obsolete
positioning, misleading maturity claims.
